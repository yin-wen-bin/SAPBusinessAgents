# GR/IR Clearing Assistant

## 目标与边界

该纵向切片按“采购订单行 + 截止日”重建 GR/IR 两侧累计数量和金额，输出未清原因、当前未清周期起始日、账龄、建议责任方和处理动作。它支持 fixture 直接运行；真实 SAP 连接通过 `SapTableGateway` 注入，不进入规则核心。

`--month YYYY-MM` 表示“截至该月月末（当前月则截至今天）的全部未清项”，不会错误排除以前月份形成的长期挂账。如只关心某段时间内有业务动作的项目，可另外使用 `--activity-from` 和 `--activity-to`；完整历史仍会加载，日期窗口只筛候选，不截断余额计算。

## 处理流

1. `GrirDataSource.list_po_items` 按公司代码、工厂、PO 筛采购订单行。
2. `load_po_history` 一次加载这些 PO 行截至分析日的完整历史。
3. 归一化约定：收货和发票为正数；收货冲销、退货、发票冲销和贷项为负数。
4. `GrirAnalyzer` 分别汇总 GR/IR 数量与金额，再按优先级分类。
5. 从当前连续未清周期的首个事件计算账龄，而不是简单使用 PO 创建日期。
6. `reporting` 输出 UTF-8 JSON 或带 BOM 的 Excel 友好 CSV 异常清单。

## 原因规则与建议

| 优先级 | 原因 | 核心条件 | 主要责任方 | 建议 |
|---|---|---|---|---|
| 1 | 退货未处理 | 存在退货，且净发票数量大于净收货数量 | 采购、供应商、AP | 获取并过账贷项，或冲销错误凭证 |
| 2 | 已收货未发票 | 净 GR 大于容差，净 IR 为零 | 供应商、AP | 催票/补票；确认无后续时再评估 MR11 |
| 3 | 已发票未收货 | 净 IR 大于容差，净 GR 为零 | 收货部门、采购 | 补收货或冲销/更正错误发票 |
| 4 | 数量差异 | GR 与 IR 净数量差超过容差 | 收货、采购、AP | 逐笔核对并补录、冲销或取得贷项 |
| 5 | 价格差异 | 数量已匹配但金额差超过容差 | 采购、AP | 更正价格或发票；MR11 仅用于已确认尾差 |
| 附加标志 | 长期挂账 | 当前未清周期账龄达到阈值（默认 90 天） | 总账、采购 | 跨部门复核；审批后再执行 MR11 |

MR11 始终作为有条件建议，不会因为达到天数阈值自动过账。生产环境应叠加公司容差、审批矩阵、期间状态和凭证留痕控制。

## SAP 数据映射

当前可执行适配器读取：

- `EKKO`：公司代码、供应商、币种、采购组。
- `EKPO`：PO 行、工厂、物料、订单数量、净价、价格单位；删除行默认跳过。
- `EKBE`：PO 历史。默认将 `BEWTP=E` 视为 GR 侧、`BEWTP=Q` 视为 IR 侧；移动类型 122/161 视为退货，102/106/123/162 视为 GR 冲销；借贷标识转换为有符号数量和金额。

不同系统的 `BEWTP/VGABE`、币种金额字段、移动类型和服务类 PO 可能有差异，上线前必须用目标系统样本校准。生产扩展建议：

- `RBKP/RSEG`：补充发票状态、冲销关系、贷项和冻结原因，支持 MIR4 追踪。
- `BKPF/BSEG`：校验 GR/IR 总账余额、凭证状态和 FBL3N 明细。
- CDS/OData/RFC 或经授权的自建接口均可实现 `SapTableGateway.read_rows`；网关负责认证、分页、字段权限和过滤语法。
- 大数据量场景先用 MB5S 等价查询/CDS 获取未清候选，再按 PO 行批量加载 EKBE，避免全表读取。

对应人工复核入口为 MB5S（未清）、ME23N（PO 历史）、MIR4（发票）、FBL3N（总账明细）和 MR11（经审批清理）。

## 接入真实 SAP

实现唯一端口：

```python
class MyGateway:
    def read_rows(self, table, fields, filters):
        # 将 filters 翻译为目标 RFC/OData/CDS 查询，并返回字段字典列表
        ...

source = SapTableGrirDataSource(MyGateway(), source_name="S4D-100")
report = GrirClearingService(source).analyze(
    AnalysisCriteria(as_of_date=date.today(), company_code="1000")
)
```

若企业接口已经直接提供规范化 PO 与历史数据，也可绕过表映射，直接实现 `GrirDataSource`。

## 异常清单字段

清单保留公司代码、工厂、PO/行、供应商、物料、币种、主原因/附加原因、严重度、GR/IR 数量与金额、差异、未清起始日、账龄、责任方、建议和关联历史凭证号。JSON 额外带查询条件、生成时间和按原因/责任方汇总。

## 已知限制

- 当前为 PO 行级聚合，不执行发票行与收货行的逐笔 FIFO/批次匹配；账龄使用“余额归零或跨零后形成的当前连续未清周期”。
- 默认假设同一 PO 行历史金额已换算到统一 PO 币种；多币种需在数据源层按 SAP 汇率与本位币规则标准化。
- 规则不代替 SAP 配置中的数量/金额容差、GR-based IV、ERS、服务采购和交货成本处理；这些应作为后续策略输入。
