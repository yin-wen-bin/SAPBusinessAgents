## 为什么业务状态仍是 inconclusive

主 Batch API 已完整分页，所以固定 Agent 的业务记录中
`source_complete=true`。但两个正库存批次没有可用效期，故
`expiry_evidence_complete=false`、`evidence_complete=false`，总体状态为
`inconclusive`，同时保留已确认的四个过期风险。

ADT 补充已按条件触发。`sap-adt-table-export` 现在能够递归展开
`MCHA/MCH1` 的 DDIC include，并以完整、只读结果确认相关底层字段；两个
正库存批次的 `VFDAT` 确实为空，因此平台继续显示“效期缺失”，而不是猜测日期。

自由查询 `run_61ac1fc5c15b4bc1` 的确定性评估有效，最终报告校验通过；固定
Agent 运行 `acceptance_5b53d242dcd4438c` 与独立基线一致。这里的
`inconclusive` 只表示两个批次的业务主数据不足以完成全部效期判断，不再表示
平台、Provider 或 Skill 被技术能力阻塞。
