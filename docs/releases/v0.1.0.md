## 中文

这是面向可信操作员的 Windows 本地预览版，发布形式为 GitHub Release 源码包。GitHub Pages 只展示静态 Agent 目录，不连接用户的 SAP，也不承载运行数据。安装步骤见[首次使用指南](../getting-started.md)。

主要能力：固定 Agent 的确定性只读执行、自由查询、Agent 草稿编写与验收、工作流组合，以及可逐封确认发送的邮件插件。Agent 目录中的“已停用”或“因证据或验收缺口受阻”条目仅供阅读，不表示当前可执行；应以详情页的生命周期和验收状态为准。

本版明确不可作为已验收可执行能力宣传的条目：已停用 `billing-dispute-classification`、`billing-output-monitor`；仍有验收或证据缺口的 `budget-rolling-forecast`、`co-month-end-allocation-settlement`、`cost-center-expense-anomaly`、`internal-order-project-control`、`production-scheduling-capacity`、`returns-credit-anomaly`、`shortage-allocation-advisor`。目录状态见[README中的生成清单](../../README.md#功能与完整目录)。

已验证的自然语言客户端组合为 `openai-codex 0.147.0` 及其绑定的 `openai-codex-cli-bin 0.147.0`。模型能否使用仍取决于本机登录账号、模型目录和系统配置中的兼容性检查，不由 SDK 版本单独保证。Python 支持 3.11 和 3.13，Node.js 使用 22 系列；发布门禁以对应 Windows CI 和全新安装结果为准。

已知限制与安全边界：

- 本地原型不提供互联网多用户部署、独立身份管理或租户隔离；不要公开 8765/4321 端口。
- 自由查询和 Agent 对话编写使用 SDK `full_access`，工作副本不是 OS 沙盒。请在可信、最小权限的本地账户下使用，并阅读[安全说明](../../SECURITY.md)。
- SAP 业务事实只以本次已核验的只读证据为依据；`inconclusive`、证据缺口或测试数据缺口不代表业务完成或验收通过。邮件发送属于独立的外部写操作，需要逐次确认。
- 企业微信尚未接入；邮件连接需由使用者完成认证、工具绑定与健康检查。
- 本预览版不附带 SAP 数据、凭据、真实验收环境或可直接运行的云服务。

## English

This is a Windows-local preview for a trusted operator, distributed as GitHub Release source. GitHub Pages hosts a static Agent catalog only; it does not connect to a user's SAP system or store runs. See [Getting started](../getting-started.md) for installation.

Features include deterministic read-only fixed Agents, free queries, Agent draft authoring and acceptance, workflow composition, and mail actions with confirmation for each send. Inactive or acceptance-blocked catalog entries are documentation, not a claim of executability. Check each Agent's lifecycle and acceptance status.

Do not present these entries as accepted executable capabilities in this release: inactive `billing-dispute-classification` and `billing-output-monitor`; acceptance- or evidence-blocked `budget-rolling-forecast`, `co-month-end-allocation-settlement`, `cost-center-expense-anomaly`, `internal-order-project-control`, `production-scheduling-capacity`, `returns-credit-anomaly` and `shortage-allocation-advisor`. See the [generated README catalog](../../README.md#features-and-full-catalog) for their recorded status.

The tested natural-language client combination is `openai-codex 0.147.0` with its bundled `openai-codex-cli-bin 0.147.0`. Actual model availability depends on the local account, model catalog and compatibility check in System settings. Supported Python versions are 3.11 and 3.13; Node.js uses the 22 series. Windows CI and clean-install results are release gates.

Known limitations and security boundary:

- This local prototype has no internet-facing multi-user deployment, separate identity management or tenant isolation. Do not expose ports 8765/4321 publicly.
- Free queries and conversational Agent authoring use SDK `full_access`; the work copy is not an OS sandbox. Use a trusted least-privilege local account and read [Security](../../SECURITY.md).
- Business facts require verified read-only evidence from the current run. An `inconclusive` result or evidence/test-data gap is not business completion or acceptance. Sending mail is a separate external write requiring confirmation each time.
- WeCom is not yet connected. Mail requires user-side authentication, tool binding and a passing health check.
- This preview includes no SAP data, credentials, live acceptance environment or ready-to-run cloud service.
