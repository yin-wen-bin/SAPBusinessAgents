## 计时规则

- 一个新查询轮次（新`run_id`）拥有独立预算。同一轮的补参、恢复共享剩余预算。
- 新增内部`harness_state.execution_clock`，保存累计执行秒数、活动片段起点、
  等待时间及代次；不增加数据库表或公开接口。
- 保持原初始执行计时边界。只有SDK调用清理已确认、平台返回等待输入后才暂停计时。
- 回答补参时，在原子消费输入的同一事务中将时钟置为排队；真正派发时恢复计时。
  等待用户和排队均不消耗剩余执行预算，重复消费仍被拒绝。
- 所有活动片段累加，保留小数精度，不因多次暂停重新获得1800秒。
- 进程内使用单调时钟；重启后读取持久化片段。活动中断的未知时间保守计入执行，
  无法确认的反向时钟变化阻断，不凭空授予预算。
- 查询阶段、报告交接阶段和硬预算继续使用原上限及原扩展规则；正式验收不套用用户暂停。
- 旧记录不自动迁移，不根据不完整历史推算或补发执行时间。
