# 五模型统一链路修复：离线候选与上线边界

## 实施范围

本候选补齐金额规范值说明、精确纠错反馈、平台派生状态解释；增加服务级范围映射及完整元数据约束；接通已审核配置来源到共享分类器和金额计算；增加原生终态Schema绑定检查、安全根字段诊断及上游协议错误诊断。

不调用真实SDK、模型、SAP或认证服务，不重试五次原查询，不运行Campaign或15项验证，不应用认证、不切换worker、不重启服务、不提交或推送。Codex与WorkBuddy共享业务校验，保留各自原生交接差异及原预算。

## 未被伪装为已解决的证据缺口

1. Supplier 与 InvoicingParty 在目标服务中的范围等价需要审核。元数据字段存在和纯内存反事实通过不能授权。注册表生产条目暂为空，相关真实计划仍明确阻断；合成服务映射仅供测试。
2. 已保存K/F核实只证明当前配置，没有2019—2022年有效区间证明。新接入链不能凭代码补造这段历史，相关真实业务分类仍unknown。
3. 当前配置来自受限ADT材料；本候选不会解密或绕过原敏感证据授权。接入该来源需要受保护适配器及独立审核，不能把它当普通公开OData行。
4. HY4与MiMo的非法终态继续拒绝；新增轨迹和离线模拟证明的是契约与反馈链，不是两模型真实纠错已成功。
5. Kimi旧运行缺少厂商详细错误，新增诊断不能恢复已经丢失的旧原因。

## 依赖与上线要求

- 新职责组件 runtime_evidence_bindings.py 纳入报告检查器绑定；其配置内容进入冻结查询契约。
- models、报告提示、金额校验、范围解析、来源分类及终态反馈变化属于实际协议／执行依赖变化，不能按“纯展示调整”自动承接。
- workbuddy_worker.py 的离线源码候选变化必须经新不可变release生效；当前已安装worker和SDK／CLI不覆盖、不升级。
- 后续上线前应冻结代码和测试证据，审核目标接入认证与必要模型协议证据；证据不足保持旧服务。真实轻量检查需另行授权，本轮不执行。
- 确认活动任务、旧写入者、清理进程退出后才能持维护锁切换。配置和历史记录不迁移、不改写，不以全量重验补偿意外失效。
- 回退保留新增原始记录和审计证据；不恢复无法读取新增协议的旧写入者。本轮未部署，无需改变正式回退指针。

## 回归入口

主要新增用例为 tests/test_five_model_unified_repair.py。与现有共享查询金额、报告、终态、范围、认证、来源语义及模拟worker用例共同运行。全部使用隔离临时状态、合成数据及模拟适配器，测试不授予业务PASS。

Windows asyncio需要标准库内部socketpair；离线网络保护只允许这个内部通道，其余业务连接拒绝。测试临时根必须显式位于隔离目录，不复用正式状态目录。

测试结果、保护审计和具体未完成项另附于本轮私有交付报告。离线通过不代表原业务问题或上游服务已真实恢复。
