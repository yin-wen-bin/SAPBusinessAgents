## 1. 本轮结论与证据边界

已完成离线回放；本轮不实施生产修复、不调用模型或 SAP、不重发原查询、不更新服务或 worker、不修改当前配置、资格及历史 PASS。

原作业实际使用国内站 `space-bunny`、SDK 0.3.247、CLI 2.141.0，而非此前讨论的 DeepSeek。后续不能擅自换模型，也不能将其他模型的成功视为本作业已经修复。

- 保存的 10 次报告调用均能复现其原有结构错误签名；9 次 `report.blocks` 为对象，另一次将完整终态包误放入 `report`。
- 10 次非法报告均可通过当前对外工具 Schema，因为 `report` 只被声明为 `{"type":"object"}`；后台 `RunPresentation` 和终态 Schema 才要求 `blocks` 为数组。
- 保存的错误正文含字段路径和约束，并未被桥接整体丢失；但当前 WorkBuddy 工具返回未设置 `isError`，Codex MCP 返回设置了 `isError=true`。锁定 worker 的实际文件与本次检查源码一致，且文件摘要符合原清单。
- 普通自由查询没有验收模式的重复失败追踪；相同非法结构连续调用 10 次仍不产生停滞终止信号。报告校验又不计入普通业务工具调用限额，因此不能指望该限额使报告纠错收敛。
- 失败结果目前仍返回一个 `validation_ref` 字符串，容易形成误导。不过现有最终保存逻辑还要求原报告调用成功，不会仅凭该字符串授予成功或资格。
- 原生终态 Schema 确实已通过独立通道传给 SDK；不能把问题说成“完全没有传 Schema”。缺口在于报告工具入参说明、最终终态和后台校验未形成一致、明确的交接契约。

原生终态 Schema 摘要与原作业保存摘要一致。历史工具注册 Schema 和完整提示没有在该作业元数据中逐字归档，故不宣称已恢复当时全部线上输入；本次使用的是脱敏保存入参，非 SDK 原始参数的逐字重放。

最后的 CLI 错误仅为 `Error in agent run`。本轮未复现真实 SDK 错误、模型推理或厂商服务异常，不能证明它由报告错误引起，也不能认定额度、网络、轮次上限或 SDK 内部缺陷。该未知项单独保留。

## 2. 修复范围与 Codex 保护

权威业务 Schema、证据检查及诊断构造保持共享，不为每个字段建立专属纠错方法。

首期只在 WorkBuddy 的报告工具注册、错误响应编码和报告纠错策略上接入修复。Codex 继续使用当前工具定义、MCP 错误编码、提示、预算、终态和重试行为；不改变其请求参数、准入或资格。共用辅助函数不意味着同时改变 Codex 已上线行为。

不改查询计划、SAP 过滤范围、工具授权、业务计算、证据判定及最终成功标准。不自动将对象包装为数组、不删未知字段、不补造缺失字段、不猜测引用、不从普通文本截取 JSON。

## 3. 报告工具 Schema 与提示对齐

1. 复用共享权威定义，为 WorkBuddy 的 `sap_final_report_validate.report` 提供明确的报告 Schema，包含双语标题、`blocks` 数组、块类型和各自内容字段、枚举、长度与额外字段限制。
2. 区分两个合法阶段：工具接收 `{"report": <presentation>}`；原生终态接收完整输出包，其中 `presentation` 是同一份已验证报告。完整终态不得充当工具的 `report`，报告对象也不得充当完整终态。
3. 工具 Schema 保留后台已有默认值及合法旧表示的兼容性；原生终态仍满足原有严格必填契约。不能直接复制一个更严格的 Schema，导致原先合法的工具调用被误拒。用规范化后语义对照验证两者的合法交集，非法结构仍直接拒绝。
4. 在 WorkBuddy 格式化交接说明中加入一个不含业务事实和有效引用的合成示例，明确 `blocks` 必须为数组、`title` 为双语对象，以及校验成功后仅按已有规则加入凭据并提交终态。示例不是备用业务答案。
5. 工具定义按冻结任务上下文生成：普通自由查询不暴露 `acceptance_projection`；只有平台签发验收契约时才暴露其准确 Schema。后台继续拒绝普通查询携带该字段，不能仅隐藏入口而放松执行检查。
6. 工具注册与提示必须引用同一份任务报告契约，不各自手写另一份业务规则。不改变 SDK 原生 Schema 编码、安装版本或模型选择。

现有 Pydantic 默认值、原生严格必填形式及业务自定义校验不是逐字相同的 JSON Schema；不以“Schema 完全相等”代替兼容和业务测试。

## 4. 可执行且安全的纠错反馈

对报告失败提供统一、由权威 Schema 和检查器生成的结构诊断，至少包括错误码、字段路径、期望类型／约束、实际类型及下一步动作。

例如 `/report/blocks` 返回“期望数组、实际对象；重建报告结构并再次校验”，而不是只有通用的“不符合 Schema”。不回显原始输入、SAP 行、原始推理、凭据或厂商日志；未知字段路径按现有脱敏规则处理。

- 明确指出工具 `report` 与原生 `presentation` 的对应关系；不能要求把整个终态包塞进 `report`。
- `ok=false` 时，面向 WorkBuddy 的响应明确 `report_validated=false`，不得将失败凭据当作可用凭据；若为接口兼容保留原诊断字符串，也必须明确不可用于终态。原历史输出不改写。
- Worker 将 `ok=false` 编码为 MCP `isError=true`，成功编码为非错误；保留同一份业务诊断正文。Supervisor、驱动、worker 不各自改写出互相矛盾的纠错文本。
- 校验成功只证明报告候选通过，不等于原生终态已收到、清理已完成或业务结果已保存。现有终态、引用、完整性、取消和清理检查继续执行。

Worker 改动必须通过新的不可变 release；保持 SDK／CLI 版本及依赖锁不变，保留当前旧 release 和历史绑定。此步骤不属于本次只读回放，也不得原地改写安装清单。

## 5. 通用、定向的报告收敛机制

先修正契约可见性和反馈，再增加停滞保护；不能只缩短调用次数来掩盖错误。

- 跟踪报告结构错误签名、候选结构进展、相关证据／评估代次和已返回的纠错说明；不依据自然语言长短判断是否进展。
- 首次失败给出精确说明，允许作业内修正。建议初始策略：同一结构阻碍在精确反馈后累计 3 次且无相关进展时，将本作业标记为“报告格式纠错未收敛”，停止该作业，清理所属进程并保留证据。阈值及计数规则需在实施时固定并测试，不新增模型调用或增加原预算。
- 修复字段类型、解除必要错误、补齐有效业务内容或完成相关证据校验可构成进展；只换文字、键顺序、请求 ID 或新增无关字段不能重置计数。
- `tool_call_id` 幂等重传不计新尝试；响应未知先恢复原调用，不自动派发新作业。
- 结构错误的修复只针对报告，不额外触发 SAP 读取；收尾阶段仍禁止新的外部读取。真正的证据不足与结构错误分别报告，不能靠格式通过掩盖业务缺口。
- 保留正常调查、编辑和测试能力，不增加整个 SDK 的全局轮次限制，不延长或重置预算，不将本作业失败扩散为整个 Runtime 或其他操作不合格。
- 停滞终止不能制造成功报告；没有有效终态时仍为未完成，并独立保存原始错误与清理结果。

机制放在共享报告职责组件中，首期由 WorkBuddy 显式采用；不改变 Codex 当前停止与终态策略。后续扩展另行评估，不复制一套 Provider 业务算法。

## 6. 离线验证及最小影响核对

使用已保存结构信息和合成值，阻断外部连接及真实 SDK 启动；真实 SAP 证据只留在现有受保护存储，不复制到新夹具或发送给模型。

必须覆盖：

- 原 10 次错误；对象／数组混淆、双语类型错误、整包误嵌套、额外字段、非法枚举、缺字段与未请求投影。
- 合法最小报告、完整严格终态、多种块、合法空结果与证据不足；表格行列、200 行上限、未知引用及不完整 Skill 证据等原检查不放宽。
- 工具 Schema 与后台合法表示兼容；终态仍按原严格 Schema 检查，不自动补值或转换非法值。
- 模拟 SDK 收到的 `isError`、错误正文与平台保存诊断一致；成功后必须交付真实终态，候选不能替代终态。
- 首次错误后成功、完全重复、等价改写、实质进展、错误交替、幂等重传、迟到结果、取消和最多 10 秒清理。
- 普通查询无验收投影、验收查询保留完整投影检查；报告校验失败不会促使平台重新读取 SAP。
- Codex 原请求、工具定义、提示、权限、预算、校验和恢复行为的离线对照；不调用 Codex 模型。

只运行本次涉及的 Python／接口与模拟 worker 回归；不重跑 15 项业务验证，不因未修改前端而重做前端构建。

在任何上线前单独列出依赖摘要变化和 SDK 接入认证影响。历史业务 PASS 保留原样；需要目标基础设施证明时按既有审计流程处理，不改摘要算法，不把离线测试登记为真实模型通过，也不默认要求全量业务重验。
