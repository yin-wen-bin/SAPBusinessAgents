# 正式验收总览

正式验收总览仅组织已有记录，不执行验收，也不授予执行或发布资格。

- 标题状态代表当前修订的有效验收结果；最近一次尝试单独显示。最近失败不能替换仍有效的结果，旧PASS也不能为新修订自动背书。
- 自动检查、有效试运行和验收准备分别显示。准备就绪不是业务PASS；证据不足不是试运行通过。
- 准备失败且没有阶段启动证据时显示“业务验收未开始”，保留原始NOT_TESTED及诊断。取消、旧修订和状态未知分别显示。
- Runtime和模型使用所属Campaign的冻结记录，缺失时显示未记录，不读取当前默认值代填历史。
- 重新验收只打开原设置确认流程。已有活动任务只查看原进度；清理未确认保持可见，并禁止开始新的验收。
- 刷新沿用只读GET；展开详情不触发执行。AI分析必须由用户明确操作，本次回归使用模拟回调。
- 案例与已有记录、技术诊断默认收起。诊断引用仍绑定原修订、来源和摘要；定位会展开对应详情。
- 发布状态由原发布判定决定。验收通过不等于全部发布条件满足，继续按钮只进行步骤导航。

642px优先使用三项状态同行；390px按实际容器宽度换行，主按钮全宽。底部导航在本步骤正常排列，不覆盖发布提示。样式仅作用于正式验收总览，不改变其他步骤或验收设置弹窗。

## Offline regression

`site/tests/acceptance-overview.browser.mjs` 使用本地模拟组件、受控回调及阻断外部请求的浏览器测试，覆盖中英文、642px/390px、两个Provider及失败、取消、清理、未知和历史结果。它不产生真实业务PASS。

验收设置、结果弹窗及后端原门禁通过既有回归核对。前端可独立构建与切换，不重启API或改变SDK、worker、认证、模型和历史记录。

## 验收设置与执行进度

- 进入验收步骤提前执行现有草稿GET的 `view=acceptance_setup` 展示模式。该模式只返回草稿标识、修订、正式Runtime快照及其绑定摘要，不组装对话、修订列表和管理详情；普通GET保持原结构。
- 同一草稿修订合并在途读取；成功预览在5秒展示窗口内复用。重新核对保留上次信息及案例，等待时显示秒数，失败时提供只读重读。核对中或失败的预览不能提交；真实受理仍使用 `expectedRuntimeDigest`、原完整预检及幂等请求。
- WorkBuddy每次准备只生成一次正式快照，再绑定统一认证修订。Provider认证修订与统一认证绑定修订不同，不可互相代填；准备期间账号、站点或系统默认变化时拒绝结果。Codex继续委托原快照入口。
- 进度窗口分为固定标题、滚动正文及固定操作栏。阶段完成必须有结果依据，不因阶段排列位置推断完成；排队、实际执行耗时与预算分别记录，预算不是预计完成时间。
- 当前案例默认展开，其余折叠，用户展开选择不被更新覆盖。连接异常、必要业务输入及清理未确认直接可见；原始诊断和下载入口收起。任务中断与业务NOT_TESTED分开显示。
- 收起、关闭及Esc只收起窗口，Campaign继续；“停止验收”调用原取消和清理链路。重新设置验收不自动提交、不强制更换案例。
- `tests/test_acceptance_runtime_binding.py`覆盖统一认证和受理至模拟基线派发，`tests/test_acceptance_setup_view.py`覆盖读取兼容；`site/tests/acceptance-runtime-progress.browser.mjs`覆盖慢响应、失败、迟到响应、输入保留和642px／390px。全部使用隔离状态及模拟边界，不产生真实业务PASS。
