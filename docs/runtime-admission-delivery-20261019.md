# Runtime 准入优化与目标草稿业务输出交付记录

日期：2026-10-19。两条工作线已分别冻结、回归并受控上线。

## 结果

- 自由查询使用内部 `RuntimeAdmissionRequest` / `PreparedRuntime`，一次同步准备得到准入结果和冻结快照。旧调用方及 Codex 保持原严格路径。
- WorkBuddy 按当前操作和权限模式定位 SDK 证明，不在普通准入中重新审核无关业务评测及历史 Campaign。模型、认证、安装、权限、取消、截止时间和派发前复核仍是硬门禁。
- 采用 `sapba.workbuddy.unfinished-jobs/1`。所有宿主作业写入使用索引→作业锁顺序和原子写入；声明先于创建进程，持久终态且清理完成后才能移出索引。迁移保留了 522 份历史作业，未知派发窗口、脏事务及未知 PID 身份继续阻断。
- 同步检查作用域只在同一线程、任务和环境内去重，结束时再次校验；不跨 `await`、排队或请求授权。并发认证复核只合并同一绑定的官方检查，不自动登录或切换账号。
- 草稿 `agent_draft_b947ebc1029ae8f81b28512c` 已经由真实前台“修改草稿”保存修订 **2**，逐轮 Diff 为 **1 → 2**，刷新后仍存在。没有直接写数据库应用候选。

## 性能

口径为“本地准入准备＋冻结绑定核对＋派发前本地检查”，不包含原生 SDK 启动或模型生成。

| 对照 | 旧路径 P50 / P95 | 新路径 P50 / P95 | 降幅 |
|---|---|---|---|
| 最终配对、交替顺序、每组 20 次热样本 | 2.910 / 3.428 秒 | 1.249 / 1.656 秒 | 57.1% / 51.7% |
| 首次上线、各 20 次热样本 | 2.645 / 3.100 秒 | 1.259 / 1.401 秒 | 52.4% / 54.8% |

最终配对的旧 `src` 和 `scripts` 均逐文件匹配实施前冻结摘要；检查使用真实只读安装与证据，没有替换资格或跳过检查。配对前曾因旧源码副本缺少辅助脚本而停止，补齐摘要一致的脚本后才执行成功比较。

所有测量制品均保留，包括一次 API 冷启动期间 P95 较差的复测（2.855 秒），以及最终代码空闲复测（P50 1.298 / P95 1.574 秒）；没有删除不利样本。配对测试用于减少不同时段机器负载的干扰。

安装校验仍是主要成本。最终空闲测量中，每个独立同步边界的安装阶段通常约 340～560 ms，证书和绑定阶段约数十 ms，未完成作业检查约 1 ms。阶段统计保存在本地报告中；任务清理和原生 SDK 消息等待不计入准入性能目标。

请求内 `Path.read_bytes/read_text` 采样由旧路径约 96 次作业文档读取降至约 10 次，其他采样由 257 次降至 112 次；该计数不是所有底层磁盘 I/O 的总数。历史增长测试禁止普通准入遍历历史作业目录；只核对索引与本次必要证据。

## 目标草稿

名称为“供应商历史未清项目与发票校验助手 / Supplier Historical Open Items and Invoice Verification Assistant”。业务域为应付账款，组件 FI-AP；目录仍为 MM，技术 ID 仍为 `free-query-b4fd09ce`，版本仍为 0.1.0。建议 ID 没有越过独立确认流程。

新增的沙箱本地规则基于原结构化证据计算：

- 四字段稳定业务键、精确重复与冲突诊断；截止日前或当天清账不属于截止日未清。
- 供应商全部未清项目与 RE 发票校验子集分别计数。
- 保留源金额符号，使用 Decimal 分币种汇总，不跨币种相加。
- 输出规范记录、业务状态、完整性、缺口及双语业务报告；资料不足返回未知数量，不能冒充完整零结果。

原 SAP 读取步骤、服务、实体、筛选、选择字段、读取限制和输入名称逐结构保持相同。`schemaVersion` 未改变，验收契约保持 `contractVersion: "1.0"`，记录粒度与事实、指标、口径同步到新的确定性输出。没有为新修订复用旧试运行或验收结论。

预检查和保存现在复用 `candidate_business_output_issues`；保存时的身份、修订、权限与事务检查仍独立执行。

真实前台作业 `agent_op_090da85d369f40a78149`：184.7 秒完成，有效原生结构化终态、实际模型身份一致、校验通过、保存成功、清理完成。第一条 SDK 响应约 6.03 秒，首条助手消息约 8.46 秒；这与本地准入耗时分开评价。

首次前台尝试没有取得终态。已确认其绑定的上游 Agent run 以通用错误结束，但平台此前漏认父级错误而继续等待。补齐了请求哈希、所属 PID 和祖先链约束下的错误识别，并覆盖无关分支不能误伤的测试；原尝试经页面取消且完成清理，旧记录保留。上游内部错误的具体原因仍未知，后续一次成功不证明供应商偶发错误已根除。

## 保留与上线

API 已通过维护锁和停止写入者核对后受控切换，当前进程源码有启动摘要绑定。前台构建及其进程未被中断。索引上线后不恢复不维护该协议的旧写入者；回退必须使用兼容读写版本，并保留新增台账和历史制品。

SDK 0.3.247、CLI 2.141.0、国内站、deepseek-v4.1-flash 和当前 immutable worker 未变。现有启用事实和实际默认选择按运行状态保留，没有按旧对话改成其他默认值。Codex 账户元数据和协议文件未变，原业务质量记录、模型检查及历史 PASS 摘要相同；只追加了明确审核的 SDK 基础设施认证。

官方认证复核正常更新了 WorkBuddy 的检查时间和观察元数据，账号身份、认证修订、站点与确认绑定未变。没有复制认证凭据。

本轮新增 SAP 工具调用为 0；没有 Campaign、15 项真实重验、发布、启停／默认切换、依赖升级、提交或推送。可信本地编写模式仍不是操作系统级隔离。
