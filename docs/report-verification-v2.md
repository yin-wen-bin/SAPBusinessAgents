# 自由查询报告验证 v2

新报告使用 `schema_version: "2.0"`。v1 的数据结构与已保存报告保持原样；不重新计算历史摘要、改写验证凭证或升级业务 PASS。

## 验证结果

规范报告及运行结果中的 `verification` 由平台生成。四个维度为 `summary_amounts`、`detail_amounts`、`business_facts`、`coverage`，各自返回 `verified`、`needs_evidence`、`failed` 或 `not_requested`，并附位置、原因和证据引用。

有效指标不因出现普通文字而降级。未结构化的业务文字仍是业务证明限制，不能仅靠引用 SAP 文件或改变 `claim_scope` 变为已验证。旧 `financial_verification` 仅作金额兼容摘要；完整性由规范报告对应的四项服务器证明判定，最终交接重新核对，不接受模型自报状态。

## 金额、单元格与正文

- 指标保留原有 `sap_money_aggregate` 引用及 Decimal 精确计算，交接时重新计算本次运行拥有的源证据。
- v2 表格的每行可用 `value_bindings` 按列键绑定来源。`kind=source` 需要本次运行的 `evidence_ref`、完整 `source_key`、`source_field`；金额同时需要注册的配对 `currency_field`。实际显示值必须在两种语言中均与规范值一致。不能跨行拼接、重复展示行或篡改币种和符号。
- 计算引用使用 `kind=calculation` 及原有 `calculation_ref`、`calculation_item`、`calculation_field`、`currency`。
- 正文使用双语 `text_template` 的 `{{name}}` 占位符，`value_bindings` 同名绑定，平台生成 `text`。最终交接复制完整 `validated_report`，保留模板、证明、默认值和验证引用。
- 模板中的自由业务判断不自动成为证明。内置 `open_items_exist` 规则仅接受平台指定的双语模板及来源于截止日未清组的正数计数，不能由模型任意扩充谓词。
- 表格的行集合须与来源或指标组相符。多个汇总组时，使用 `row_set_binding` 指明计算组；截断、缺行或覆盖集合不一致保留覆盖缺口。

例如平台计算出 `300.00`，模型可提交 `合计 {{total}}` / `Total {{total}}`，平台填入数值。正文中其余业务判断的证据状态单独显示，不能因为金额引用成功就声称全报告已经验证。

## 最终业务范围

用户通过公共请求 `input.answer_scope` 确认最终范围；该值不能由模型工具调用写入。结构为 `filters` 和 `categories`，过滤项仅允许 `{field, operator, value}`，操作符为 `eq`、`le`、`ge`；类别来自平台来源语义目录。

此范围是对原问题的进一步限定，不能删除供应商、公司、日期或其他已确认条件。没有用户确认时，后续窄查询不能自动关闭宽口径读取的缺口。平台生成的范围收据绑定问题、输入、契约、使用证据及探索/前置/最终角色；原读取与配置重评收据保留不变。

范围内未知分类、配置有效期不明或分页不完整仍需补证。只有存在覆盖完整确认范围的证据，且范围内分类与金额成立，探索证据中的范围外问题才不阻断最终结果。单纯移除引用无效。

## 跨接口关联

新增只读 `sap_relation_resolve` 接受 `relation_id`、`evidence_ref`。它不发起 SAP 读取，而是用审核规则、完整本次源证据和权威元数据生成 `relation_ref` 及目标计划。目标计划带 `scope_relation_ref` 和完整复合键 `tuple_filters`，范围门禁在派发前重新核对。

注册表 v1 继续有效；v2 在原 `scope_mappings`、`configuration_sources` 外增加 `relations`。规则必须包含审核引用、源和目标实体、等长且不重复的字段组、保留公司维度、`one_to_one`/`many_to_one` 基数，以及 `system_context_digest`。系统上下文是配置的私有 SAP 环境文件的 SHA256；配置变更即撤销旧关系适用性，摘要不能代替人工业务审核。

不能凭编号相同把 `Supplier` 与 `InvoicingParty` 当作等价，也不能将复合键拆成独立列表交叉组合。缺审核、源数据不完整、行键缺失、错误公司、规则/配置变化或跨运行证明均被拒绝。生产配置不添加推测映射；真实证据不足的关系保持禁用。

## 验收和上线

离线测试覆盖双 Runtime 的共享 Broker、旧记录读取、规范报告交接、来源范围与关联拒绝路径。使用原案例保存证据回放，只验证新规则的表现，不改写原运行或授予业务 PASS。

候选从当前激活版本派生，经冻结内容回归、接入准入检查后，由现有 `activate-code` 空闲维护流程切换 API 与前台并核对实际绑定。无需升级 SDK，不自动登录、切换模型、扩大预算或访问真实 SAP。
